## upd11 — таблица примитивов и линеаризация диспетчера (double-VM)

- Новый модуль `packages/core/src/analysis/primitives.ts`:
  - `resolvePrimitives` — находит таблицу, ключи которой числа, а значения — хостовые функции (`buffer.readu8`, `bit32.band`, `table.pack`, `unpack`, …). Возвращает карту «номер → символ», категории, «дырки» в домене и (если таблица анонимна, как в `setmetatable({...},{}):bw(...)`) угадывает имя по частотности `X[n]`-индексаций.
  - `primitiveCallSites` — считает вызовы `X[n](...)` по каждому разрешённому ключу.
  - `linearizeDispatch` — обходит дерево интервалов `if F <= … then …` внутри `while`/`repeat`, пересекает ограничения с учётом `==` и `~=` (ветка `~=` инвертируется), и выдаёт листья: диапазон состояний → вызываемые методы. Понимает диспетчер, разнесённый по нескольким соседним if-цепочкам.
  - `formatPrimitives` / `formatDispatch` — текстовые отчёты.
- Экспортировано из `packages/core/src/index.ts` (типы: `PrimitiveTable`, `PrimitiveEntry`, `PrimitivesReport`, `IntervalDispatch`, `DispatchLeaf`, `LinearizeReport`).
- Проверка на целевом чанке (3 287 229 Б, double-VM):
  - таблица примитивов `d`: 154 числовых ключа (127 в домене ≤1023), 80 разрешены в хостовый API, `buffer=26 bit32=10 table=6 string=11 coroutine=8 global=19`; автоматически найдены отсутствующие в литерале ключи `18, 24, 26` (назначаются в рантайме).
  - диспетчер `F` линеаризован в 10 блоков — ровно как при ручном разборе: `0..3 → xw/ww`, `4..5 → pw`, `6..8 → Cw`, `9..12 → Lw`, `13..17 → gw`, `18..21 → dw`, `22..23 → Fw`, `24..26 → zw`, `27..31 → Rw`, `32+ → Sw`.
  - диспетчер опкодов по `D` даёт 20+ листьев с полным набором чисел состояний.
- `npx tsc -p packages/core/tsconfig.json --noEmit` — 0 ошибок; прогон `scratch/primitives_run.ts` на чанке ~2.5 с (парс 1.5 с, примитивы 0.9 с, диспетчер 0.1 с).

## upd10 — Superflow: прямой fetch, outline в clean(), гейт инлайна

- `analysis/opcodes.ts`, `detectRoles`: форма `op = code[pc]` (плоский массив кода, операнды в отдельных таблицах) теперь даёт роли `code`/`pc`; `inst` выставляется только когда handler'ы индексируют сам объект инструкции. Классификация `vm` дополнена случаем `fetch && stack && leaves >= 8`. Проверка на NEW_SAMPLE_3_TEST: `rB` распознан как `vm` (83 листа, `code=S`, `pc=I`), а не `switch`.
- `passes/outline.ts`: инлайн методов выполняется только при замкнутом пространстве методов (`!selfEscapes && !(dynReadKinds & K_STR) && !(dynWriteKinds & K_STR)`). Раньше 100 инлайнов оставляли определения в таблице и дублировали тела: вывод 0.80 МБ → 2.37 МБ; теперь 1.62 МБ без дублей. Добавлен `entryOnly` (по умолчанию): обрабатываются только таблицы, сразу вызываемые как конструктор `({...}):entry()`; обычные классы/модули не трогаются.
- `index.ts`: `reinlineOutlined` встроен в `clean()` до основных проходов; опция `outline`, статистика `outlineInlined` / `outlineSlots` / `outlineRemoved`; `deobfuscate` пробрасывает `outline`.
- NEW_SAMPLE_3_TEST (Superflow): **100/100** после clean, 0 ошибок парсинга, 174 handler'а (opcodes 1..175), 231 слот outline свёрнут, 3 CFF сняты. Payload — custom-байткод; `vm_lift` его не берёт (см. `results/NEW_SAMPLE_3_TEST/REPORT.md`).
- Регрессия: 18/18 реальных обфускаторов (`apps/web/public/samples`) проходят `clean()` с 0 ошибок парсинга (`out/pipeline-regress.log`); typecheck без новых ошибок.

## upd09 — регрессионный стенд и универсальный for-loop

- `tools/readable_regress.sh` + `tests/readable/t01…t05`: синтетические тесты-ловушки для каждого прохода (порядок вычислений, побочные эффекты, multi-return, замыкания, `#`, метатаблицы, shadowing, break, изменяемый лимит, float-шаг). Каждый тест запускается в lua54 до и после проходов, вывод сравнивается. Итог: 5/5.
- `recoverForLoops`: понимает `local i = A; while i <= B do … i = i + K end` (самая частая форма в обычном коде); захват считается только по свободным ссылкам (параметр вложенной функции с тем же именем больше не блокирует).
- Сознательно НЕ конвертируются: переменная читается после цикла, лимит `#t`/вызов (for вычисляет лимит один раз), тело меняет лимит или переменную, замыкание захватывает переменную.
- TEST-PRISM3: 104/104 идентично.

## upd08 — чистка неиспользуемых локалов `pruneLocals`

- Новый проход `packages/core/src/passes/prunelocals.ts`: из объявлений `local a, b, c` без значений убираются имена, на которые нигде в функции (включая вложенные) нет ссылок; пустое объявление удаляется.

## upd07 — восстановление `for`-циклов `recoverForLoops`

- Новый проход `packages/core/src/passes/forloops.ts`: `i = A; while i <= B do …; i = i + K end` → `for i = A, B, K do … end` (и `>=` с отрицательным шагом).
  - Проверки: i — локал/параметр, не захвачен замыканием; тело не пишет i и не содержит continue/goto; предел — литерал или неизменяемый локал; знак шага совпадает со сравнением; i мёртв после цикла.
- Хелперы анализа живости (`deadAfter`, `reads`, `mentions` …) экспортируются из `inlinetemps.ts` для других проходов.
- `tools/readable_cli.ts` включает проход в цикл до стабилизации.
- TEST-PRISM3: восстановлено **2** цикла (`for i = 1, 40`, `for i = 1, 8`), 512 → **508** строк. Вывод 104/104 идентичен.

## upd06 — инлайн сквозь чистые вызовы и через строки

- `inlineTemps`: вызовы чистых встроенных функций (`PURE`: tostring, math.*, string.*, bit32.*, Vector3.new …) больше не блокируют подстановку.
- «Стабильные» выражения (литералы, незахваченные локалы, стандартные глобалы, чистые вызовы и операторы над ними) подставляются и после вызовов, и через промежуточные стабильные присваивания, которые не переписывают их переменные.
  - Допущение: скрипт не переопределяет стандартные глобалы (print, tostring, math …) по ходу работы.
- TEST-PRISM3: инлайнов 184 → **203**, 531 → **512** строк, аудит **72/100**, остатков 277 → **257**. Вывод 104/104 идентичен.

## upd05 — свёртка таблиц в конструктор `foldTables`

- Новый проход `packages/core/src/passes/tablefold.ts` (экспорт `foldTables(chunk)`): `x = {}` / `table.create(N)` + записи `x.a = …`, `x[2] = …`, `x[k] = …` → один конструктор `{ a = …, [2] = … }`. Последовательные числовые ключи становятся позиционными элементами.
  - Безопасно: у свежей таблицы нет метатаблицы, порядок вычисления сохраняется; значения не должны упоминать x, при повторе ключа свёртка останавливается; если в значении есть вызов, x не должен быть виден вложенным функциям.
- `tools/readable_cli.ts` теперь крутит сахар → свёртка → инлайн до стабилизации.
- TEST-PRISM3: свёрнуто **65** записей, ещё **+1** инлайн. 597 → **531** строка, аудит 65 → **71/100**, остатков 372 → **277**, `h[N]` 49 → 21. Вывод 104/104 идентичен.

## upd04 — инлайн одноразовых временных `inlineTemps`

- Новый проход `packages/core/src/passes/inlinetemps.ts` (экспорт `inlineTemps(chunk)`): `x = E; S(x)` → `S(E)`.
  - Только если x — локал функции, объявлен один раз, не захвачен замыканием, читается ровно один раз и мёртв после использования (с учётом циклов и break/continue).
  - Порядок вызовов не меняется; многозначные вызовы в хвосте списка оборачиваются в `( )`; не тащит вызовы в правую часть and/or; функции с goto пропускает.
- CLI: `node --import tsx tools/readable_cli.ts <lift.lua> <out.lua>` (makeReadable + inlineTemps + makeReadable).
- TEST-PRISM3: заинлайнено **183** временных. 780 → **597** строк, аудит 61 → **65/100**, остатков 560 → **372**, h_N 486 → 298. Вывод 104/104 идентичен.
- Пример: 8 строк `h_14 = h_2(); h_14 = h_14 * 38; …` → `h_13 = math.floor(h_2() * 38) + 2`.

## upd03 — проход читаемости `makeReadable` (часть 1)

## upd01 — проверка лифта без Luau + честный вердикт сравнения

- `packages/tools/src/compat54.ts` (новое): Luau → Lua 5.4 шим, сохраняет номера строк (ошибки указывают на ту же строку лифта).
  - `continue` → `goto __continueN` + метка перед `end` цикла (если тело заканчивается `return`, он оборачивается в `do … end`);
  - generalized iteration `for k, v in t do` → `__prism_iter(t)` (next / `__iter`, как в Luau);
  - целые литералы ≥ 2^24 пишутся как double — LCG/хэши (`(s * 1103515245 + 12345) % 2^32`) округляются как в Luau;
  - однострочная прелюдия: `bit32`, `table.create/find/clear/clone/freeze`, `math.round/clamp/sign`, `string.split`, `getfenv`, `typeof`, `task`, печать чисел как в Luau (`5`, а не `5.0`).
- `luau_run`: движок `engine: auto | luau | lua54` (auto = настоящий Luau, если найден, иначе Lua 5.4 + шим); путь к Luau может быть папкой;
  упавший или «немой» прогон теперь `NOT VERIFIED`, а не ложное `0/0 — OUTPUT IDENTICAL`.
- Проверено на TEST-PRISM3: stage-2 лифт (790 строк, 3 прото) + `PROTOS[1](false)()` → **104/104 OUTPUT IDENTICAL** с оригиналом.
- `results/TEST-PRISM3/`: текущий лифт, stage-1 clean, отчёт auto_lift и отчёт проверки.
